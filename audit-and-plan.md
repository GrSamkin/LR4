## 2. Архитектурный план оптимизации

Принцип: **не переписывать, а упорядочить**. Внутри одного файла сохраняем строгий порядок секций и добавляем «шапку» с оглавлением.

### Целевая структура файла (порядок не меняется, только нумерация и границы)

```
<!DOCTYPE html>
<head>
  meta / theme-color / OG
  <style>
     1. Токены (:root, color-scheme)
     2. Reset + базовые элементы
     3. Утилиты (.container, .icon, .sr-only, .skip-link, .btn)
     4. Компоненты по секциям: header → hero → catalog → advantages →
        bestseller → slider → faq → cta → footer → to-top/toast
     5. Адаптив (1200 → 992 → 768 → 480)
     6. prefers-reduced-motion
  </style>
</head>
<body>
  skip-link
  SVG-спрайт
  header / overlay / main / footer / to-top / toast-box
  <script>
     0. Утилиты ($, $$, prefersReducedMotion, throttle)
     1. Toast
     2. Cart (localStorage)
     3. Кнопки «В корзину» (делегирование на document)
     4. Меню
     5. Фильтры
     6. Таймер
     7. Слайдер
     8. FAQ
     9. Форма
    10. To-top
    11. Reveal (IntersectionObserver)
    12. Мелочи (год)
  </script>
</body>
```

### Ключевые архитектурные решения (дёшево и по делу)

1. **Один делегированный обработчик вместо N.** Сейчас `$$('[data-add]')` вешает слушатель на каждую кнопку. Заменить на один `document.addEventListener('click')` с проверкой `e.target.closest('[data-add]')` — новые карточки начнут работать без переинициализации.
2. **Один `resize`-обработчик** с `requestAnimationFrame`-троттлингом вместо трёх.
3. **Единый `setState`-подход для UI-состояний**: `is-open`, `is-active`, `is-visible` — уже используется, оставляем как контракт, но синхронизируем с ARIA (`aria-expanded`, `aria-pressed`, `aria-selected` → `aria-current`).
4. **Утилиты вместо inline-стилей**: `.icon--sm` (18px), `.btn--block` (100%), `.sprite` (скрытый спрайт), `.sr-only`.
5. **CSS-токены уже есть** — добавляем только `color-scheme:dark` и `--focus` (не обязательно).
6. **Документацию** из HTML-комментария переносим в этот `audit-and-plan.md` (или оставляем 5 строк-подсказок), чтобы не раздувать разметку.

## 4. Что сознательно НЕ делаем (вне лимита 15 минут)

- Полный рефакторинг JS в модули/классы — не нужен для лабораторной, риск сломать рабочее.
- Реальная корзина с количествами, панелью и оформлением заказа — отдельная задача.
- Полноценный focus-trap в мобильном меню.
- Переписывание CSS на утилитарный подход (в проекте уже есть БЭМ-подобные классы — это плюс).

## 5. Критерии приёмки

1. HTML валиден, дубликатов `id` нет.
2. Консоль браузера чистая (без ошибок и отладочных `console.log`).
3. Все интерактивные элементы достижимы клавиатурой и имеют видимый фокус.
4. Форма: ошибки озвучиваются и связаны с полями (`aria-describedby`, `aria-invalid`).
5. Слайдер: неактивные отзывы скрыты от скринридера.
6. Проект по-прежнему — **один файл** [`index.html`](index.html), без библиотек и сборки.
7. Внешних библиотек и сборки нет — проект открывается двойным щелчком по файлу.
